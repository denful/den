Den ships reusable aspect providers under `den.batteries` (also accessible via
the aliases `den.provides` and `den._`). Each battery contributes
NixOS/Darwin/home-manager modules to hosts and users that include them.

Batteries fall into two categories:

- **Opt-in** -- you include them explicitly in `den.default.includes`, `den.aspects.<name>.includes`, or `den.schema.<kind>.includes`.
- **Auto-activated** -- Den activates them via built-in policies. They define new classes or integration layers that work without explicit inclusion. These are **not** values under `den.batteries` -- there is nothing to include; their headings below name the class they add.

---

## System

### `den.batteries.define-user`

Creates OS-level user accounts (`users.users.<name>`) with a `home` directory (`/Users/<name>` on Darwin, `/home/<name>` elsewhere), plus `isNormalUser` on NixOS. Also sets `home.username` and `home.homeDirectory` for Home Manager. Works on NixOS, Darwin, and standalone Home Manager homes.

**Opt-in.**

```nix
den.default.includes = [ den.batteries.define-user ];
```

### `den.batteries.hostname`

Sets the system hostname from `den.hosts.<name>.hostName`. Works on NixOS and Darwin.

**Opt-in.**

```nix
den.default.includes = [ den.batteries.hostname ];
```

### `os` class

Provides an `os` convenience class whose contents land in the host's own OS class -- `nixos` on NixOS hosts, `darwin` on Darwin hosts. This lets you write platform-agnostic host configuration without duplicating it across classes.

**Auto-activated.** The `os-to-host` policy is in `den.default`, so it fires in every scope that binds a host -- `os` content on a user aspect reaches that user's host too. Hosts of any other class (and standalone homes) ignore `os` content.

```nix
den.aspects.my-host = {
  os.networking.hostName = "foo";
};
```

<Aside title="Source" icon="github">
[`modules/aspects/batteries/os-class.nix`](https://github.com/denful/den/blob/main/modules/aspects/batteries/os-class.nix)
</Aside>

### `user` class

Provides a `user` class that forwards settings into the host's `users.users.<userName>` at OS level. Instead of writing the full `nixos.users.users.alice` path, you write directly into the `user` class. Inside a `user` module, `config` is the host's OS config, also available as `osConfig`.

**Auto-activated** through the `user-to-host` policy in `den.default`. `user` is the default of `users.<name>.classes`, so a user gets it unless you replace that list.

```nix
den.aspects.alice.user = { pkgs, ... }: {
  packages = [ pkgs.hello ];
  extraGroups = [ "wheel" ];
};
```

</Aside>

### `den.batteries.primary-user`

Marks a user as the primary (admin-level) user. On NixOS, adds `wheel` and `networkmanager` groups. On Darwin, sets `system.primaryUser`. On WSL, sets `defaultUser`.

**Opt-in.**

```nix
den.aspects.alice.includes = [ den.batteries.primary-user ];
```

### `den.batteries.user-shell`

Sets the user's login shell at both OS and Home Manager levels. Enables `programs.<shell>.enable` and sets `users.users.<name>.shell`.

**Opt-in.** Takes a shell name as argument.

```nix
den.aspects.alice.includes = [
  (den.batteries.user-shell "fish")
];
```

### `den.batteries.mutual-provider`

Delivers what a user provides to its hosts into each host's own configuration. It covers the user-to-host half of [mutual providers](/guides/mutual/): `provides.to-hosts` and `provides.<host>`. The host-class part of that content (`nixos` on a NixOS host, `darwin` on a Darwin host) goes to the host. Its other classes, such as `homeManager`, stay with the user.

Host-to-user providers (`provides.to-users`, `provides.<user>`) are not part of this battery. They are built in and always apply.

**Included by default** in `den.schema.host.includes`, so `to-hosts` and `provides.<host>` work without any setup. To opt out, exclude it for every host or for one host:

```nix
# every host
den.schema.host.excludes = [ den.batteries.mutual-provider ];

# one host
den.hosts.x86_64-linux.igloo.excludes = [ den.batteries.mutual-provider ];
```

It has no effect on standalone homes, which have no host configuration to deliver into.

<Aside type="caution">
In this release a user's content still reaches its hosts by nesting, with or
without this battery, so excluding it doesn't stop `provides.to-hosts` content
from reaching a host yet. The next release keeps a user's content with the
user ([#694](https://github.com/denful/den/issues/694)); from then on, this
battery is how `provides.to-hosts` reaches a host.
</Aside>

<Aside title="Source" icon="github">
[`modules/aspects/batteries/mutual-provider.nix`](https://github.com/denful/den/blob/main/modules/aspects/batteries/mutual-provider.nix)
</Aside>

### `den.batteries.host-aspects`

Projects user-relevant classes (like `homeManager`) from the host's aspect tree onto users who opt in. Any `homeManager` key defined in the host aspect is forwarded to the user's home-manager evaluation.

**Opt-in.**

```nix
den.aspects.tux.includes = [ den.batteries.host-aspects ];
```

<Aside title="Source" icon="github">
[`modules/aspects/batteries/host-aspects.nix`](https://github.com/denful/den/blob/main/modules/aspects/batteries/host-aspects.nix)
</Aside>

### `den.batteries.user-aspects`

Lets a host accept its users' whole host-class output: everything a user's aspect tree writes to `nixos`, `darwin` or `os`, not only what it sends through `provides`. It is the user-to-host counterpart of `host-aspects`.

**Opt-in, host side only.** Include it on a host or on the host kind. Included on a user, it does nothing, because a user cannot grant itself access to a host.

```nix
# igloo accepts all of its users
den.aspects.igloo.includes = [ den.batteries.user-aspects ];

# igloo accepts tux only
den.aspects.igloo.includes = [
  (den.batteries.user-aspects { users = [ "tux" ]; })
];

# every host accepts all of its users
den.schema.host.includes = [ den.batteries.user-aspects ];
```

When several includes apply to one host, the host accepts every user any of them names. The bare form accepts all users.

<Aside type="caution" title="User host-class content still reaches hosts">
In this release a user's `nixos`, `darwin` and `os` content still reaches every
host the user lives on, whether or not the host includes `user-aspects`
([#694](https://github.com/denful/den/issues/694)). The next release keeps
that content with the user unless the host accepts it. Include `user-aspects`
on the hosts that rely on it, so they keep working after that change.
</Aside>

<Aside title="Source" icon="github">
[`modules/aspects/batteries/user-aspects.nix`](https://github.com/denful/den/blob/main/modules/aspects/batteries/user-aspects.nix)
</Aside>

### `wsl` class

Enables WSL support on NixOS using the NixOS-WSL project. For an enabled host it imports the NixOS-WSL module, sets `wsl.enable = true`, resolves a `wsl-host` entity, and routes the `wsl` class into the host's `wsl.*` options.

**Auto-activated** when `host.wsl.enable = true` on a `nixos` host. Requires `inputs.nixos-wsl`, or set `host.wsl.module` to the NixOS-WSL module yourself.

```nix
den.hosts.x86_64-linux.igloo.wsl.enable = true;

# or on every host (only nixos hosts are affected)
den.schema.host.wsl.enable = true;

# `wsl` class content becomes the host's `wsl.*` NixOS options
den.aspects.igloo.wsl.startMenuLaunchers = true;
```

`den.batteries.primary-user` sets `wsl.defaultUser` through this class.

<Aside title="Source" icon="github">
[`modules/aspects/batteries/wsl.nix`](https://github.com/denful/den/blob/main/modules/aspects/batteries/wsl.nix)
</Aside>

### `den.batteries.forward`

A generic forwarding primitive that creates custom Nix classes by routing module contents from one class into a target submodule path. The `homeManager`, `hjem`, and `maid` integrations use it internally. (The `os`, `user`, and `wsl` classes use the lighter `den.lib.policy.route` instead -- see [Policies](/reference/policies/).)

**Opt-in.** Used when building custom classes. See the [Custom Classes](/guides/custom-classes/) guide.

```nix
den.batteries.forward {
  each = lib.singleton user;
  fromClass = _: "myClass";
  intoClass = _: host.class;
  intoPath = _: [ "some" "path" ];
  fromAspect = _: user.aspect;
};
```

<Aside title="Source" icon="github">
[`modules/aspects/batteries/forward.nix`](https://github.com/denful/den/blob/main/modules/aspects/batteries/forward.nix)
</Aside>

### `den.batteries.import-tree`

Recursively imports plain `.nix` files, taking the class from the directory name: every `_<class>/` directory under the given root (`_nixos/`, `_darwin/`, `_homeManager/`, or any other class) is imported into `<class>`. Useful for migrating existing configurations.

**Opt-in.** Requires `inputs.import-tree`. The `provides.host`/`user`/`home` forms look in `<root>/<entity name>/`, so `./hosts` above reads `./hosts/<host>/_nixos/` and so on.

```nix
# Import per host
den.schema.host.includes = [
  (den.batteries.import-tree.provides.host ./hosts)
];

# Import per user
den.schema.user.includes = [
  (den.batteries.import-tree.provides.user ./users)
];

# Import per standalone home
den.schema.home.includes = [
  (den.batteries.import-tree.provides.home ./homes)
];

# Import for a specific aspect
den.aspects.laptop.includes = [
  (den.batteries.import-tree ./disko)
];
```

<Aside title="Source" icon="github">
[`modules/aspects/batteries/import-tree.nix`](https://github.com/denful/den/blob/main/modules/aspects/batteries/import-tree.nix)
</Aside>

### `den.batteries.flake-scope`

Exposes `lib`, `inputs`, and `den` to aspect pipeline functions **and** to
class modules (`nixos`, `homeManager`, …) -- the generic (non-flake-parts)
counterpart of `inputs'`/`self'`. A parametric aspect or a class module can
then destructure these alongside entity args:

```nix
den.default.includes = [ den.batteries.flake-scope ];

den.aspects.my-aspect = { host, inputs, lib, ... }: {
  nixos = { pkgs, ... }: {
    environment.etc."version".text = inputs.nixpkgs.lib.version;
  };
};
```

Values are tagged `pipelineOnly` (class-wins collision policy), so
class-module-native values (e.g. NixOS's own `lib` from `_module.args`)
win silently over the flake-scope ones.

**Opt-in.**

<Aside title="Source" icon="github">
[`modules/aspects/batteries/flake-scope.nix`](https://github.com/denful/den/blob/main/modules/aspects/batteries/flake-scope.nix)
</Aside>

## Home Environments

The three home environments share one activation rule: a host enables one when at least one of its users lists the class in `users.<name>.classes`. Writing a `homeManager` (or `hjem`, `maid`) key on an aspect is **not** enough -- `classes` defaults to `[ "user" ]`.

```nix
den.hosts.x86_64-linux.igloo.users.alice.classes = [ "homeManager" ];

# or for every user
den.schema.user.classes = lib.mkDefault [ "homeManager" ];
```

Each adds a pair of host options under its option path (`home-manager`, `hjem`, `nix-maid`): `enable` (defaults to "some user has the class") and `module` (defaults to the module from the flake input). Set `module` to use a pinned or patched module, or to supply one without the flake input.

### `homeManager` class

Integrates [home-manager](https://github.com/nix-community/home-manager) as a user environment class. Imports the appropriate home-manager NixOS or Darwin module and merges `home-manager.users.<name>` from each user's `homeManager` class. Inside a `homeManager` module, `osConfig` is the host's config.

**Auto-activated** on NixOS and Darwin hosts (see above). Requires `inputs.home-manager` unless `host.home-manager.module` is set. Aspects in `den.schema.hm-host.includes` are included on every host that enables home-manager.

```nix
den.aspects.alice.homeManager = {
  programs.git.enable = true;
};
```

<Aside title="Source" icon="github">
[`modules/aspects/batteries/home-manager.nix`](https://github.com/denful/den/blob/main/modules/aspects/batteries/home-manager.nix)
</Aside>

### `hjem` class

Integrates [hjem](https://github.com/feel-co/hjem) as an alternative home environment. Imports hjem's NixOS or Darwin module and merges `hjem.users.<name>` from each user's `hjem` class.

**Auto-activated** on NixOS and Darwin hosts (see above). Requires `inputs.hjem` unless `host.hjem.module` is set.

```nix
den.aspects.alice.hjem = { pkgs, ... }: {
  packages = [ pkgs.ripgrep ];
};
```

<Aside title="Source" icon="github">
[`modules/aspects/batteries/hjem.nix`](https://github.com/denful/den/blob/main/modules/aspects/batteries/hjem.nix)
</Aside>

### `maid` class

Integrates [nix-maid](https://github.com/viperML/nix-maid) as an alternative home environment. NixOS only. Merges configuration into `users.users.<name>.maid` for each user's `maid` class.

**Auto-activated** on NixOS hosts (see above). Requires `inputs.nix-maid` unless `host.nix-maid.module` is set.

```nix
den.aspects.alice.maid = {
  programs.helix.enable = true;
};
```

## Package Management

### `den.batteries.unfree`

Allows specific unfree packages by name via `nixpkgs.config.allowUnfreePredicate`. Emits into `nixos`, `darwin`, and `homeManager`. When included on a user, the names are also allowed on the host's OS config, so `home-manager.useGlobalPkgs = true` and users with only the `user` class work too. The predicate builder is automatically included in `den.default`.

**Opt-in.** Takes a list of package names as argument.

```nix
den.aspects.laptop.includes = [
  (den.batteries.unfree [ "nvidia-x11" "steam" ])
];
```

## Battery identity and excludes

A battery that takes arguments (`unfree`, `insecure`, `user-aspects`,
`tty-autologin`, `vm-autologin`, `import-tree`) gives each use an identity
under the battery's own, `den/batteries/<name>`. That identity decides when
two uses are one, and what an exclude reaches.

**Exclude the battery, or one use of it.** Excluding the battery removes every
use the exclude reaches; excluding one use removes that one only:

```nix
den.aspects.igloo.includes = [
  (den.batteries.unfree [ "z1" ])
  (den.batteries.unfree [ "z2" ])
];
den.aspects.igloo.excludes = [ den.batteries.unfree ];             # removes both
den.aspects.igloo.excludes = [ (den.batteries.unfree [ "z1" ]) ];  # removes z1, keeps z2
```

An exclude follows the aspect it is written on (#613's tree position), as any
aspect exclude does: a host's `excludes` doesn't reach what its users include.
Exclude a user's battery on that user.

**Argument sets are sets.** `unfree`, `insecure` and `user-aspects` name a
use by its sorted, deduplicated argument list, so the order of names doesn't
matter and the same set used twice applies once. Distinct sets stay distinct,
whatever they contain: `user-aspects { users = [ "all" ]; }` is not the bare
battery, and `[ "a,b" ]` is not `[ "a" "b" ]`.

**An `import-tree` root is its whole path.** Two roots that share a last
directory name (`./a/disko` and `./b/disko`) are two uses, and so are two
`import-tree.provides.host` roots for one host. One root included twice is
one use. A root is identified by its store path, so a path literal (`./dir`,
copied as part of the flake) and an interpolated string (`"${./dir}"`, copied
as its own store object) are two roots: written both ways, the same files
are imported twice. Write each root one way. Messages show a root without its
store hash, for example `source/hosts/igloo`.

## Usage Patterns

### Global defaults

Apply batteries to all hosts, users, and homes:

```nix
den.default.includes = [
  den.batteries.define-user
  den.batteries.hostname
  den.batteries.inputs'
];
```

### Per-aspect inclusion

Apply batteries to specific aspects:

```nix
den.aspects.alice.includes = [
  den.batteries.primary-user
  (den.batteries.user-shell "zsh")
  (den.batteries.unfree [ "vscode" ])
];
```

### Per-entity-kind inclusion

Apply batteries to all entities of a kind:

```nix
den.schema.user.includes = [
  den.batteries.define-user
];
```

### Composing batteries with configuration

Batteries compose freely with inline configuration:

```nix
den.aspects.my-admin = {
  includes = [
    den.batteries.primary-user
    (den.batteries.user-shell "fish")
    { nixos.security.sudo.wheelNeedsPassword = false; }
  ];
};
```
