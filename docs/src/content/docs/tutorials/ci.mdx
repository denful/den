The CI template is Den's comprehensive test suite. It tests every feature using [nix-unit](https://github.com/nix-community/nix-unit). This is the **best learning resource** for understanding exactly how Den behaves.

Every `.nix` file under `modules/` is auto-imported by [import-tree](https://github.com/denful/import-tree) — the flake just hands `./modules` to it. To add a test, drop a new file in; there is no central list to edit.

## Test Categories

The tables below list representative suites. Each test file declares one `flake.tests.<suite>` and holds several `test-*` cases.

### Core Features

| Suite | What It Tests |
|-------|---------------|
| `conditional-config` | Conditional imports using host/user attributes |
| `default-includes` | `den.default` applying to all hosts/users |
| `host-options` | Custom host attributes, hostName, aspect names |
| `top-level-parametric` | Context-aware top-level aspects |
| `auto-parametric` | Parametric aspects auto-dispatched by the pipeline |

### Bidirectional & Providers

| Suite | What It Tests |
|-------|---------------|
| `user-host-mutual-config` | Host→user and user→host config flow |
| `mutual-provider` | Mutual provider mechanism |
| `policy-provide` | Policy-driven `provide` effects |

### Policies

| Suite | What It Tests |
|-------|---------------|
| `policies` | Policy declaration and activation |
| `policy-excludes` | Policies excluding includes |
| `route` | Route effects |

### Batteries

| Suite | What It Tests |
|-------|---------------|
| `define-user` | User definition across contexts |
| `primary-user` | Primary user groups |
| `user-shell` | Shell configuration |
| `unfree` | Unfree package predicates |
| `tty-autologin` | TTY autologin service |
| `vm-autologin` | VM autologin service |
| `import-tree` | Auto-importing class dirs |
| `flake-parts` | `inputs'` and `self'` providers |

### Advanced

| Suite | What It Tests |
|-------|---------------|
| `angle-brackets` | All bracket resolution paths |
| `namespaces` | Local, remote, merged namespaces |

| `standalone-homes` | Standalone Home-Manager configs |

### Bug Regressions

Every fixed bug gets a pinned regression test, named after its issue. A couple of examples:

| Suite | What It Tests |
|-------|---------------|
| `deadbugs-static-include-dups` | Deduplication for packages/lists |
| `deadbugs-namespace-deep-aspect` | Deep aspect access from external flakes |

## External Provider

The `provider/` subdirectory is a **separate flake** that exports a namespace called `provider`. It is consumed by namespace tests to verify cross-flake aspect consumption. The exporting flake imports `den.flakeModule` and registers the namespace as an output with `den.namespace "provider" true`:

```nix
# provider/modules/den.nix
{ inputs, ... }:
{
  imports = [
    inputs.den.flakeModule
    (inputs.den.namespace "provider" true)
  ];

  provider.tools.provides.dev.provides.editors = {
    nixos.programs.vim.enable = true;
  };
}
```

The second argument to `den.namespace` (`true`) marks the namespace as a flake output so other flakes can import it.

## Running CI Tests

From the Den root against your local checkout:

```console
just ci
```

You can run a single suite (or a sub-path below `flake.tests`) by passing its name:

```console
# Any attr-path below flake.tests works, e.g. a whole suite:
just ci c3.wsl-class

# …or a single case within it:
just ci c3.wsl-class.test-wsl-forwards
```

The default `just ci` is fast but cannot show error diffs and skips tests that assert via nix-unit `expectedError`. Use `just ci-deep` for full nix-unit output with diffs:

```console
just ci-deep wsl-class
```

## Writing New Tests

Copy `modules/new-test.nix` as a starting point, rename the suite and case, then assert with `expr` / `expected`:

```nix
{ denTest, ... }:
{
  flake.tests.new = {
    test-something = denTest (
      { den, igloo, ... }:
      {
        den.hosts.x86_64-linux.igloo.users.tux = { };

        den.aspects.base =
          { host, ... }:
          {
            nixos.networking.hostName = host.hostName;
          };

        den.aspects.igloo.includes = [ den.aspects.base ];

        expr = igloo.networking.hostName;
        expected = "igloo";
      }
    );
  };
}
```

`denTest` provides handy fixtures as function arguments: `den` (the live `den` config), `igloo` (`nixosConfigurations.igloo.config`), `tuxHm` (`igloo.home-manager.users.tux`), plus `iceberg`, `apple`, `pinguHm`, and a `trace` helper. Drop your new file under `modules/` and `git add` it before running nix — import-tree only sees tracked files.
